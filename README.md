# 물리학 2 대표문항 및 풀이 배포 사이트

제38대 서울대학교 공과대학 학생회 [새결] 교육국의 정적 사이트입니다.
`index.html`에 화면, 스타일, 단원 데이터가 포함되어 있으며 별도 빌드가 필요하지 않습니다.

## 반영한 자료

- 제공된 `할리데이_물2_통합본.zip` 안의 PDF 7개(총 73쪽)를 사용합니다.
- PDF 본문에서 21~40장 문항 번호를 확인해 입력했습니다. 21장 20번을 제외한 212개를 안내하며, PDF 쪽수 안내는 표시하지 않습니다.
- `할리데이 11판 한글판 표지.jpg`를 `img/cover11.jpg`로 복사했습니다.
- 배포 PDF 파일명은 사이트 규칙에 맞추었습니다. 21~23장 PDF는 요청한 문구를 삭제했으며, 나머지 6개 PDF는 ZIP 원본과 같습니다.
- 단원 구성은 실제 파일에 맞춰 28~29장, 30~33장으로 정리하고 37~40장을 추가했습니다.

| 사이트 단원 | ZIP 원본 파일 | 페이지 수 |
| --- | --- | ---: |
| 21~23장 | 할리데이_21장-23장.pdf | 5 |
| 24~25장 | 할리데이_24장-25장.pdf | 6 |
| 26~27장 | 할리데이_26장-27장.pdf | 8 |
| 28~29장 | 할리데이_28장-29장.pdf | 4 |
| 30~33장 | 할리데이_30장-33장.pdf | 28 |
| 34~36장 | 할리데이_34-36장.pdf | 9 |
| 37~40장 | 할리데이_37장-40장.pdf | 13 |

사용자 요청에 따라 21~23장 PDF 2쪽의 20번 항목(문제와 그림이 잘려 있어 풀이 불가라는 문구)을 삭제했습니다.
사이트의 21장 문항 목록에서 20번과 관련 안내도 제외했습니다.
해당 줄 외의 PDF 이미지 픽셀과 5쪽 구성을 보존했습니다. 제공된 ZIP 원본은 변경하지 않았습니다.

## GitHub Pages 배포

- 사이트: https://yebe9.github.io/physics2_problemzip/
- 저장소: https://github.com/yebe9/physics2_problemzip

`.github/workflows/pages.yml`이 `main` 브랜치에 변경 사항을 올릴 때마다 자동으로 배포합니다.
GitHub 저장소의 **Settings → Pages → Source**는 **GitHub Actions**를 사용합니다.
배포 진행 상황은 저장소의 **Actions** 탭에서 확인할 수 있습니다.

워크플로는 `index.html`, `img/`, `downloads/`만 배포합니다.
표지와 PDF는 상대 경로를 사용하므로 GitHub Pages의 저장소 하위 주소에서도 작동합니다.
`tmp/`와 `output/`은 Git에서 제외되며, 작업용 스크립트와 문서도 사이트 배포 산출물에 포함되지 않습니다.

별도 수동 배포가 필요하면 `tools/package.ps1`로 `output/physics2-site/`와
`output/physics2-site.zip`을 만들 수 있습니다. ZIP에는 `index.html`, `netlify.toml`, `img/`,
`downloads/`만 들어갑니다. `netlify.toml`은 기존 호스팅 호환용이며 GitHub Pages에서는 사용하지 않습니다.
기존 Netlify 사이트는 변경하지 않았습니다.

## 로컬 확인

```powershell
python tools/preview.py
```

브라우저에서 `http://127.0.0.1:8765`를 열면 됩니다.
표지와 PDF는 배포 사이트와 동일한 상대 경로로 제공됩니다.

## 화면 이동 및 테스트

단원을 선택하면 History API에 상세 화면을 기록합니다. 브라우저 뒤로가기는 단원 목록으로,
앞으로가기는 방금 본 단원으로 이동합니다. 사이트의 `← 뒤로 가기`도 같은 방문 기록을 사용합니다.
상세 화면을 새로고침해도 해당 단원이 유지되며, 목록에서 다시 뒤로가면 이전 사이트로 정상 이동합니다.
별도 URL 경로를 만들지 않아 GitHub Pages의 하위 경로 설정을 바꿀 필요가 없습니다.

```powershell
node tools/test-navigation.cjs
```

7개 단원에 대해 브라우저 뒤로/앞으로 가기, 내부 뒤로 가기, 새로고침 복원, 포커스 복원,
중복 방문 기록 방지와 잘못된 단원 입력을 검사합니다. 이 테스트는 배포 전에도 자동 실행됩니다.

## 다음 자료 갱신

1. `index.html`의 `data` 객체에서 `problems`(문항 번호), `files`(PDF 경로)를 수정합니다.
2. `downloads/`에 새 PDF를 넣습니다. 파일명은 `할리데이 <장 범위> 팁 및 해설.pdf` 규칙입니다.
3. 수정 사항을 커밋하고 GitHub `main` 브랜치에 올리면 자동으로 배포됩니다.
4. 수동 배포용 ZIP도 필요하면 `tools/package.ps1`을 실행합니다.

## 검증

- 수정하지 않은 PDF 6개의 SHA-256을 ZIP 원본과 대조했습니다.
- 수정한 21~23장 PDF는 삭제한 한 줄 외에 모든 이미지 픽셀이 원본과 같은지 확인했습니다.
- 로컬 HTTP로 내려받은 PDF 7개의 내용이 현재 배포 파일과 일치합니다.
- 7개 단원 카드의 상세 이동, 뒤로 가기, 문항 번호, 다운로드 링크를 브라우저에서 확인했습니다.
- 표지 표시와 모바일 화면을 확인했습니다.
